# Nexora 0.2.9 — Diagnostics & Operator Health

Nexora 0.2.9 turns diagnostics into a unified runtime health system backed by live subsystem state.

## Runtime implementation

- Added `NexoraHealthMonitor` as the unified local operator-health aggregator.
- Health is sourced from real runtime objects rather than simulated dashboard values.
- Added overall and per-subsystem health states for synchronization, video, streaming, playlists, and permissions.
- Added authority player ID, authority epoch, authority heartbeat age, accepted media revision, and stale-authority reporting.
- Added real synchronization drift measurement by comparing the accepted authoritative media clock with backend-reported playback time.
- Added configurable drift warning and critical thresholds.
- Added backend readiness, fallback status, backend fault code/message, and recovery-health reporting.
- Added stream lifecycle, failure, recovery-generation, and reported-latency visibility.
- Added playlist active/current state, queue count, request count, history count, quarantine count, failure state, and revision visibility.
- Added permission lock state, local role, denied-control count, and denied-administration visibility.
- Added runtime platform labeling for PC, PCVR, Android, Quest/Android VR, and iOS build targets.
- Added transition-driven diagnostics so health changes and faults are logged when they change instead of spamming the history ring every sample.
- Added explicit logs for backend fault transitions, stream lifecycle/failure transitions, stale authority/recovery, rejected stale snapshots, denied permission attempts, and playlist quarantine growth.
- Added operator-readable multiline health snapshots through `BuildOperatorSummary()` and `CaptureOperatorSnapshot()`.
- Added `NexoraOperatorHealthBridge`, a concrete Udon integration bridge that pushes the live summary and key health fields into any operator UI/console receiver and invokes `OnNexoraHealthUpdated`.
- The UI bridge can suppress unchanged pushes while still updating when meaningful operator state or drift changes.
- Existing `NexoraDiagnostics` circular history remains the structured event store with source, severity, local timestamp, sequence number, lifetime counters, and recent-summary support.

## Health policy

Health levels are `UNKNOWN`, `HEALTHY`, `WARNING`, and `CRITICAL`.

Examples of critical conditions include stale authority, excessive synchronization drift, exhausted/missing video backend, terminal stream failure, exhausted playlist failure budget, or missing permissions enforcement on a configured health monitor.

Examples of warning conditions include aging snapshots, moderate drift, fallback video operation, backend-not-ready state, stream connecting/buffering/recovery, and quarantined or currently failing playlist entries.

Optional subsystems that are not assigned report `UNKNOWN` and do not automatically poison overall health.

## Package version

- `com.nexora.diagnostics`: 0.2.9

The diagnostics package consumes the current live telemetry contracts from Nexora Sync 0.2.6, Video 0.2.6, Streaming 0.2.8, Playlists 0.2.7, and Permissions 0.2.7.

## 0.2.9 exit gate

When Nexora misbehaves, an operator must be able to determine the current authority, revision, drift, backend state/fault, stream state/recovery, playlist health, permission state, platform, and recent fault history from the runtime diagnostics system without inventing or manually reconstructing those values.

Health transitions must be based on live subsystem state, and a UI/console must have a concrete Udon bridge for consuming that state.

## No-stubs policy

Every item listed above has a concrete runtime implementation. Placeholder dashboards, hard-coded `HEALTHY` values, TODO collectors, mock telemetry, interfaces without producers, or UI labels not connected to live subsystem state do not count as implementation.

## Validation status

The runtime implementation is committed to `main`. Unity 2022.3.22f1 + VRChat SDK + UdonSharp compile validation and multiplayer Build & Test remain required before 0.2.9 is considered compile/runtime certified.
