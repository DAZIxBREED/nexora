# Nexora 0.2.6 — Permissions & Command Security

Nexora 0.2.6 moves permission enforcement below the UI and into the authoritative command paths.

## Runtime changes

- `NexoraMediaState` now requires `NexoraAccessControl.AuthorizeTransport(...)` before load, play, pause, stop, seek, volume, loop, playback-rate, generic commit, or generic command mutation.
- Authorization happens before ownership acquisition, so a denied user cannot seize the synchronized media-state object as a side effect of a forbidden command.
- Direct calls to generic `Commit` and `CommitCommand` are protected as well as the friendly transport methods.
- Rejected transport commands are counted with action, player ID, and local timestamp telemetry.
- `NexoraAuthorityLease.RecoverLease()` and `TransferLeaseToLocal()` now require administrator authorization.
- Automatic master stale-lease recovery remains functional through a private recovery path and does not rely on public command bypasses.
- Playlist mutations now use the playlist-specific permission policy rather than the generic control policy.
- The permissions package now supports synchronized minimum roles for transport, playlists, streaming, automation, unlocked global controls, locked global controls, and administration.
- Effective permission is the stricter of the global lock policy and the action-specific minimum role.
- Added a local circular authorization audit ring recording action, role, allow/deny result, player ID, and time.
- Added `NexoraProtectedControlGroup` to disable CanvasGroup interaction/raycasts and protected colliders while presenting authorized, unauthorized, and locked visual states.

## Default lock behavior

The default locked minimum role remains `DJ`, which permits DJ, Moderator, Owner, and Master roles while excluding Guest and Trusted roles under the current role ordering.

## 0.2.6 exit gate

A manually fired transport, playlist, authority-recovery, or policy-management Udon command must not bypass the role policy. UI locking is presentation and input prevention; command-path checks remain the authoritative security boundary.

## No-stubs policy

Every item listed above has a concrete runtime code path. Package manifests, empty classes, TODO methods, and UI-only enforcement do not count toward this release.

## Validation status

The implementation is committed to `main`. It still requires Unity 2022.3.22f1 + VRChat SDK + UdonSharp compile validation and multiplayer Build & Test verification before 0.2.6 is considered compile/runtime certified.
