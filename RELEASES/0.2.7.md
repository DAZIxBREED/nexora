# Nexora 0.2.7 — Full Playlist Engine

Nexora 0.2.7 replaces the old single-list/one-queued-item model with a synchronized playlist runtime designed for persistent multiplayer state and late-join reconstruction.

## Runtime implementation

- Multiple configured playlists using catalog start/count ranges and synchronized active-playlist selection.
- Synchronized current media selection.
- Fixed-capacity synchronized queue with append, queue-next, indexed removal, reorder, and clear operations.
- Synchronized request queue with requester player IDs, duplicate suppression, approval-to-queue, and rejection.
- Dedicated request permission threshold separate from playlist-management permission.
- Synchronized playback history with previous-track restoration.
- Repeat-current and repeat-playlist modes.
- Deterministic synchronized shuffle seed with bounded fallback to sequential selection.
- Failure counters and per-entry failure tracking.
- Failure quarantine with configurable failures-before-quarantine threshold.
- Automatic failed-item skipping and bounded consecutive-failure budget.
- Queue entries take priority over shuffle/sequential selection.
- Request, queue, history, quarantine, shuffle, and active playlist state are carried in synchronized variables so late joiners reconstruct current state from persistent data rather than transient network events.
- Playlist mutations remain protected by Nexora 0.2.6 command-path permissions.
- Global locked-control policy still overrides request and playlist permissions when the UI/system is locked.

## Networking model

The playlist behaviour uses manual synchronization. Mutations take ownership, update the synchronized state, increment `playlistRevision`, and call `RequestSerialization()`. Important state is represented as synchronized variables/arrays rather than one-shot events so late joiners receive the current queue and playlist state.

All synchronized arrays are initialized to non-null arrays in accordance with VRChat Udon synchronization requirements.

## Package versions

- `com.nexora.playlists`: 0.2.7
- `com.nexora.permissions`: 0.2.7

Other packages retain independent versions when their runtime code did not change.

## 0.2.7 exit gate

A late joiner must be able to reconstruct the active playlist, current item, queue, requests, history, repeat/shuffle settings, quarantine state, and playlist revision from synchronized state. Queue management and request submission must remain subject to the appropriate Nexora role policy.

## No-stubs policy

Every feature listed above has a concrete runtime implementation. Empty classes, placeholder queue APIs, simulated playlist state, TODO methods, and event-only state that cannot recover late joiners do not count as implementation.

## Validation status

The runtime implementation is committed to `main`. Unity 2022.3.22f1 + VRChat SDK + UdonSharp compile validation and multiplayer Build & Test remain required before 0.2.7 is considered compile/runtime certified.
