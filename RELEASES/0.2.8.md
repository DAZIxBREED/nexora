# Nexora 0.2.8 — Streaming Engine

Nexora 0.2.8 replaces the old watchdog-plus-retry layer with an authoritative live-stream runtime.

## Runtime implementation

- Added synchronized stream lifecycle states: idle, connecting, buffering, live, recovering, failed, and stopped.
- Added synchronized stream source URL, source type, stream revision, recovery generation, actor ID, lifecycle timestamp, live-edge timestamp, and reported latency.
- Added source classification for HLS (`.m3u8`), DASH (`.mpd`), provider-style live URLs, direct media, and unknown sources.
- Added permission-protected stream start, stop, operator recovery, and live-edge marking using `AuthorizeStreaming(...)`.
- Added startup readiness timeout and transition into bounded recovery.
- Added buffering detection and buffering-grace recovery.
- Added playback-progress health sampling and stable-live confirmation using consecutive healthy samples.
- Added bounded reconnect scheduling through `NexoraReconnectPolicy`.
- Added recovery exhaustion handling and synchronized failed state.
- Added live-edge latency telemetry and synchronized reported latency.
- Added local health counters for startup timeouts, buffering samples, healthy samples, watchdog recoveries, recovery count, and failed recoveries.
- Recovery decisions are authority-only; non-owner clients observe health but cannot compete for recovery ownership.
- Updated `NexoraStreamWatchdog` so it no longer runs an independent recovery loop. It observes backend faults/stalls and delegates recovery to the authoritative stream controller.
- Backend fallback remains owned by `NexoraVideoBackendRouter`; the stream controller calls the router recovery path rather than duplicating backend-selection logic.
- New stream starts still flow through `NexoraMediaState` when available, preserving Nexora command-path transport authorization and the single authoritative media-state model.

## Package version

- `com.nexora.streaming`: 0.2.8

The package depends on the existing secured `com.nexora.sync` / `com.nexora.video` 0.2.6 runtime and `com.nexora.permissions` 0.2.7.

## 0.2.8 exit gate

A live stream must have an explicit synchronized lifecycle, detect startup/buffering/stall failure, recover through bounded authority-owned retries, coordinate backend fallback without a second recovery authority, expose health/latency telemetry, and enter a terminal failed state when its recovery budget is exhausted.

## No-stubs policy

Every feature listed above has a concrete runtime path. A retry class without lifecycle ownership, a watchdog that only logs, fake health values, TODO provider handlers, or duplicate local recovery loops do not count as implementation.

## Validation status

The runtime implementation is committed to `main`. Unity 2022.3.22f1 + VRChat SDK + UdonSharp compile validation and long-running multiplayer Build & Test remain required before 0.2.8 is considered compile/runtime certified.
