# Nexora 0.2.4

Nexora 0.2.4 begins the real playback-backend milestone. This release replaces the previous backend-contract-only layer with a concrete VRChat video backend that directly operates `BaseVRCVideoPlayer` implementations.

## Implemented runtime behavior

### Concrete VRChat playback backend

`NexoraVRCVideoBackend` now directly performs:

- URL acquisition through `LoadURL` or `PlayURL`
- play
- pause
- stop
- seek
- local loop restart
- volume application through configured AudioSources
- playback-time reporting
- duration capture
- backend-ready reporting
- VRChat video error handling
- recovery reloads

The same concrete adapter can wrap VRChat's Unity Video or AVPro player because both derive from `BaseVRCVideoPlayer`.

For a Unity Video backend, leave `preferPlayUrl` disabled. For an AVPro/live-stream backend, enable `preferPlayUrl` so URL acquisition uses `PlayURL`.

### VRChat video lifecycle callbacks

The backend consumes real Udon video callbacks:

- `OnVideoReady`
- `OnVideoStart`
- `OnVideoPlay`
- `OnVideoPause`
- `OnVideoEnd`
- `OnVideoLoop`
- `OnVideoError`

These callbacks update Nexora's router readiness, playback time, errors, and recovery state.

### Global URL request gate

`NexoraVideoRequestGate` enforces a shared local request interval across Nexora video backends. VRChat rate-limits video URL requests globally per user, so each backend must share the same gate when more than one video player exists in a world.

The gate tracks grants and denials and tells deferred backends when the next request window opens.

### Platform checks

The concrete backend rejects non-HTTPS media URLs in Android/Quest builds before attempting playback.

The router retains independent primary and fallback slots for:

- PC / PCVR
- Android / Quest
- iOS build targets

The iOS route is an architectural target and still requires validation in the actual target VRChat/iOS environment before it is considered certified.

### Automatic backend failover

`NexoraVideoBackendRouter` now supports a primary and fallback backend per platform.

It:

- resets to the primary backend on a new media URL
- counts consecutive severe backend faults
- distinguishes transient not-ready state from severe faults
- switches to the platform fallback after a configurable severe-fault threshold
- transfers URL, time, volume, and loop settings to the fallback
- invokes backend recovery after failover
- records backend generations and failover counts

## Package versions

- `com.nexora.video`: 0.2.4
- `com.nexora.streaming`: 0.2.4

Streaming was advanced because it directly depends on the video package and its recovery contract.

Other packages retain their independently versioned releases.

## Required scene wiring

For each concrete VRChat backend:

1. Add `NexoraVRCVideoBackend` to the GameObject that receives the VRChat video events.
2. Assign a `BaseVRCVideoPlayer` implementation:
   - `VRCUnityVideoPlayer` for the Unity Video path, or
   - `VRCAVProVideoPlayer` for AVPro/live-stream playback.
3. Assign the shared `NexoraVideoBackendRouter`.
4. Assign the same `NexoraVideoRequestGate` to every Nexora video backend in the scene.
5. Assign the backend's AudioSources if Nexora should control their volume.
6. Enable `preferPlayUrl` for AVPro/live-stream backends.
7. Place the concrete backend UdonBehaviour into the router's appropriate PC, Android/Quest, or iOS primary/fallback slot.

## Platform intent

- PC/PCVR: Unity Video and AVPro backend paths.
- Quest/Android: VRChat video backend path with HTTPS enforcement and shared request throttling.
- iOS: backend slot and common playback contract exist, but actual runtime behavior remains certification-gated.
- Windows/Linux: repository and Unity authoring remain cross-platform targets.

## No-stub rule

This release only counts the video backend as implemented because the runtime path now reaches the actual VRChat video player methods and consumes the actual VRChat video lifecycle events. A router slot or interface declaration alone does not count as a backend.

## Validation status

The implementation is committed to `main`. API choices were checked against current VRChat creator documentation and known Udon video-player usage. The project still requires Unity 2022.3.22f1 + current project VRChat SDK + UdonSharp compile testing and Build & Test runtime validation before Nexora 0.2.4 is compile-certified.
