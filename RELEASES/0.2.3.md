# Nexora 0.2.3

Nexora 0.2.3 is a resiliency and operator-control release. After review, thin implementations in recovery, diagnostics, permissions, and playlist failure handling were replaced with complete runtime behavior rather than being left as scaffolding.

## Highlights

- Added explicit video backend fault codes for not-ready, load failure, playback failure, stalls, unsupported media, missing platform backends, and exhausted recovery.
- Added backend fault counters, recovery counters, fault messages, and active-backend validation.
- Reworked stream recovery to honor the reconnect policy's actual backoff delay instead of recovering immediately.
- Added pending-recovery state, ready-grace timing, healthy/stalled sample counters, reset behavior, and bounded recovery exhaustion.
- Added playlist queueing, previous-item history, synchronized failure counts, a configurable consecutive-failure budget, failed-item skipping, queued-item priority, stop-on-exhaustion behavior, and explicit success/failure reset paths.
- Added permission decisions for control and administration separately, configurable synchronized minimum roles, per-action auditing, actor/role/result tracking, allowed/denied counters, and policy mutation methods.
- Expanded diagnostics into a real circular runtime history with source names, severity, timestamps, sequence numbers, lifetime counters, current stored warning/error counts, recent-summary generation, indexed history access, console mirroring, clear, and counter reset behavior.

## No-stub rule

A package version is not considered implemented merely because its manifest, class shell, or API name exists. Runtime features documented as part of a Nexora release must contain executable behavior. Planned features must remain documented as planned and must not be represented by empty or pass-through methods.

## Platform intent

The backend fault and recovery model remains platform-neutral and supports Nexora's PC/PCVR, Meta Quest, Android, and iOS backend-routing architecture. Unity authoring continues to target Windows and Linux development workflows.

## Validation status

The runtime implementations are committed to main. Unity 2022.3.22f1 + VRChat SDK + UdonSharp compile/runtime certification remains required before calling this release production-certified.
